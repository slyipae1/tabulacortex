# Synthetic example: `sales.xlsx`

All data in this workbook is fictional and generated by `make_sample_workbook.py`. No real person, customer or organisation is represented.

## Workbook contents

- Sheet `sales_2025`: title row, metadata row, header row (`订单号`, `日期`, `地区`, `渠道`, `产品`, `销售额`, `订单数`), 8 data rows and a footer row with an aggregate note.
- Sheet `regions`: `地区`, `责任团队`, `季度目标` for three regions.

A reasonable schema design would create a `sales_2025` fact table and a `regions` dimension table joined on `地区`.

Use these after uploading `sales.xlsx` and starting the initial design.

| Step | Prompt | Expected outcome |
| --- | --- | --- |
| 1 | “Start initial design / 开始初始设计” | Parsed structures for both sheets and an initial Mermaid ER diagram. |
| 2 | “Rename the sales table to sales_orders and keep the footer note as metadata.” | Table renamed; footer retained as metadata, not as a data row. |
| 3 | “Add a foreign key from sales_orders.地区 to regions.地区.” | Foreign key shown in the updated ER diagram. |
| 4 | “Create database / 创建数据库” | A SQLite file under `created_DBs/`. |

| 6 | “2025 年每个月的订单数量是多少？” | SQL grouping by month of 日期 with SUM(订单数). |
| 7 | “线上渠道和线下渠道的销售额分别为多少？” | SQL grouping by 渠道 with SUM(销售额). |
| 8 | “销售额最高的产品是什么？” | SQL grouping by 产品 ordered by SUM(销售额) descending, limit 1. |

Exact numbers depend on the agent-generated SQL and on the LLM endpoint; verify the generated SQL in the execution history before trusting an answer.
